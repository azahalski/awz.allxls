# API профилей модуля `awz.allxls` — описание для ИИ

REST-контроллер `Awz\Allxls\Api\Profiles` (`bitrix/modules/awz.allxls/lib/api/profiles.php`).
Все вызовы — через `BX.ajax.runAction('awz:allxls.api.profiles.<action>', {data: {...}})`.
Формат: `awz:allxls.api.<контроллер>.<экшен>`. Префиксы: `Authentication` + `CloseSession`.
Ошибки возвращаются в `errors[]` с кодами `UPPER_SNAKE` (см. ниже для каждого экшена).

Мастер создания/редактирования профиля — 4 шага (каждый шаг = свой экшен):

| Шаг | Экшен | Что делает |
|-----|-------|-----------|
| 1 | `save` | базовые поля профиля |
| 2 | `saveFile` | файл-источник и приёмник |
| 3 | `settings` (чтение) / `saveSettings` (запись) | листы, колонки, сопоставление |
| 3+ | `fields` | список полей назначения |
| 3+ | `createProperty` / `propertycheck` | создание/проверка свойств инфоблока |

---

## 1. `save` — шаг 1: создание/обновление профиля

**Экшен:** `awz:allxls.api.profiles.save`

Параметры:

| Параметр | Тип | По умолч. | Описание |
|----------|-----|-----------|----------|
| `id` | int | 0 | ID профиля; `0` — создание нового |
| `fields.NAME` | string | — | Название профиля (обязательно, непустое) |
| `fields.ACTIVE` | `Y\|N` | `Y` | Активность |
| `fields.SECTION_ID` | int | 0 | ID раздела профилей |
| `fields.DESC` | string | `''` | Описание |
| `fields.TYPE` | `import\|export` | `import` | Тип профиля (после создания не меняется через этот экшен) |
| `params` | array | `[]` | Зарезервировано, игнорируется |

Ответ: `{id: int, nextStepUrl: string}` — `nextStepUrl` ведёт на шаг 2 (`/bitrix/admin/awz_allxls_profiles_edit.php?id=...&step=2`).

Коды ошибок: `NAME_EMPTY` (пустое имя), `NOT_FOUND` (id>0 не найден), `CRON_RUNNING` (профиль выполняется cron-процессом), `PROCESS_NOT_DONE` (незавершенная обработка — сначала «Завершить обработку» на шаге 4), ошибки ORM, `EXCEPTION`.

Гварды `CRON_RUNNING`/`PROCESS_NOT_DONE` действуют и для `saveFile`, и для `saveSettings` (при живой cron-блокировке без heartbeat дольше 3 минут блокировка снимается и редактирование разрешается).

## 2. `saveFile` — шаг 2: файл и приёмник

**Экшен:** `awz:allxls.api.profiles.saveFile`

| Параметр | Тип | По умолч. | Описание |
|----------|-----|-----------|----------|
| `id` | int | 0 | ID профиля (обязателен, >0) |
| `file_path` | string | — | Путь от корня сайта **или внешняя ссылка** `http(s)://...`. Импорт: локальный файл должен существовать; внешняя ссылка скачивается в кеш на cron/агенте (`/upload/awz.allxls/cache/profile_<id>_<md5(url)>.<ext>`, `.gz` распаковывается). Экспорт: `/upload/awz.allxls/...` с расширением `csv\|xlsx` (файл создаётся при экспорте) |
| `proxy` | string | `''` | Прокси (только импорт; для экспорта принудительно очищается). Используется и для скачивания внешнего источника |
| `csv_delimiter` | string | `,` | Разделитель CSV; любой одиночный символ (иначе сбрасывается в `,`) |
| `csv_encoding` | `utf8\|cp1251\|other` | `utf8` | Кодировка CSV |
| `csv_encoding_custom` | string | `''` | Произвольная кодировка (используется только при `csv_encoding=other`) |
| `xml_paths` | string | `''` | Пути до повторяющихся элементов XML/YML (обязателен для `xml\|yml`-источника): `items->item`, разделители списка — запятая/`;`/перевод строки, вложенность — `->` или `/`. Сохраняется разобранным массивом `[["PATH","SEGMENTS"],...]` в `SETTINGS.XML_PATHS` |
| `file_cache_lifetime` | int | `-1` | TTL кеша внешнего источника, сек (`SETTINGS.FILE_CACHE_LIFETIME`; `0` — обновлять при каждом запуске, по умолчанию 7200). `-1` (не передан) — не перезаписывает сохранённое значение |
| `dest_type` | `iblock\|orm` | `iblock` | Приёмник: инфоблок или ORM-сущность |
| `iblock_id` | int | 0 | ID инфоблока (обязателен при `dest_type=iblock`) |
| `orm_file` | string | `''` | Путь к PHP-файлу ORM-класса (при `dest_type=orm`; должен существовать, без `..`, расширение `.php`) |
| `file_ext` | string | `''` | Явный тип файла источника (для ссылок/FTP без расширения): `''` (авто, по расширению пути, `.gz` распаковывается) \| `csv\|xlsx\|xls\|xml\|yml\|json`; сохраняется в `SETTINGS.FILE_EXT` |
| `max_params` | int | 0 | Макс. количество колонок (параметров) из файла импорта в настройках шага 3 (колонки сверх лимита не показываются и не сохраняются; `0` — без ограничения; `SETTINGS.MAX_PARAMS`; `settingsAction` отсекает COLUMNS листов) |
| `export_filter` | string | `''` | JSON-фильтр выборки элементов для экспорта (только TYPE=export; валидируется как JSON, сохраняется в `SETTINGS.EXPORT_FILTER`; передается в сервис-источник экспорта) |

Экспорт: расширение файла выгрузки — `csv|xlsx|json`; формат хранится в `SETTINGS.EXPORT_FILE_EXT` (для экспорта `.json` проверка `XML_PATHS` не применяется — источник здесь сервис-приёмник).

Значения сохраняются в `SETTINGS` профиля: `FILE_PATH`, `FILE_EXT`, `PROXY`, `CSV_DELIMITER`, `CSV_ENCODING`, `CSV_ENCODING_CUSTOM`, `XML_PATHS`, `FILE_CACHE_LIFETIME`, `MAX_PARAMS`, `EXPORT_FILTER`, `DEST_TYPE`, `IBLOCK_ID`, `ORM_FILE`.

Ответ: `{id, file_path, proxy, csv_delimiter, csv_encoding, csv_encoding_custom, xml_paths, file_cache_lifetime, max_params, external (bool — источник-ссылка), dest_type, iblock_id, orm_file, nextStepUrl (step=3)}` (`file_cache_lifetime` — `null`, если не передан).

Коды ошибок: `NOT_FOUND`, `CRON_RUNNING`, `PROCESS_NOT_DONE`, `FILE_EMPTY`, `FILE_INVALID` (`..` в пути), `FILE_NOT_EXISTS` (импорт, локальный файл), `FILE_EXPORT_INVALID` (экспорт: не `/upload/awz.allxls/` или не csv/xlsx/json), `XML_PATHS_EMPTY` (xml/yml/json-источник без путей; для JSON допустим один сегмент пути, для XML/YML — минимум два), `EXPORT_FILTER_INVALID` (невалидный JSON-фильтр), `DEST_IBLOCK_EMPTY`, `DEST_IBLOCK_NOT_FOUND`, `ORM_FILE_INVALID`, `ORM_FILE_NOT_EXISTS`, `EXCEPTION`.

### 2.1. `filecachestatus` — статус кеша внешнего источника

**Экшен:** `awz:allxls.api.profiles.filecachestatus`

| Параметр | Тип | Описание |
|----------|-----|----------|
| `id` | int | ID профиля |

Ответ: `{external: bool, ready: bool, age: int (сек), lifetime: int (сек), file_path}`. Для локального файла — `external: false, ready: true`. Используется шагом 3 для опроса, пока файл по ссылке ещё не скачан cron-ом/агентом. Ошибок не выбрасывает.

## 3. `settings` — шаг 3: чтение листов и колонок

**Экшен:** `awz:allxls.api.profiles.settings`

| Параметр | Тип | Описание |
|----------|-----|----------|
| `id` | int | ID профиля |
| `headerRows` | array | Переопределение строки заголовков на лету: либо по ключам `SHEET1`/`SHEET2`..., либо по индексам листов, либо плоский список |

Ответ: `{id, file_path, sheets: [...]}`. Каждый лист (через `ProfilesHelper::buildSheetData`): имя листа, ключ `SHEETn`, `HEADER_ROW`, заголовки колонок, до 20 строк-сэмплов. Для CSV — один лист (побайтовое чтение), для XLSX — все листы (FastXlsReader), для XML/YML — листы по `XML_PATHS` (`buildXmlSheets`, `HEADER_ROW` всегда 1, первый элемент листа = строка 1), для JSON — листы по `XML_PATHS` (`buildJsonSheets`, тот же контракт, один сегмент пути). Тип файла берется из `SETTINGS.FILE_EXT` либо по расширению пути.

Для XML/YML строится дерево категорий (`categories->category`, элементы `<category id/parentId>` сканируются по всему файлу независимо от `XML_PATHS`) — сохраняется в `SETTINGS.CAT_TREE` и возвращается в ответе как `cat_tree`; в каждый лист (кроме листа категорий) добавляется синтетическая колонка `category_path` (путь по дереву, `|` — вложенность, `;` — множественность).

Колонки листов отсекаются по `SETTINGS.MAX_PARAMS` (шаг 2, `limitSheetColumns`): колонки сверх лимита не возвращаются и не сохраняются.

Внешний источник (ссылка): файл подтягивается в кеш с учетом TTL; если кеша еще нет — ответ `{id, file_path, file_cache: 'pending', file_cache_status, file_cache_refresh, sheets: []}` (шаг 3 показывает «ожидаем скачивание», опрос — `filecachestatus`).

Коды ошибок: `NOT_FOUND`, `FILE_EMPTY`, `FILE_NOT_EXISTS`, `XML_PATHS_EMPTY`, `EXCEPTION`.

## 4. `saveSettings` — шаг 3: сохранение настроек листов

**Экшен:** `awz:allxls.api.profiles.saveSettings`

| Параметр | Тип | Описание |
|----------|-----|----------|
| `id` | int | ID профиля |
| `sheets` | array | Список листов (порядок = порядок в файле) |
| `customFields` | array | Кастомные поля: `[{NAME, CODE}]` (пустой CODE — транслит названия); сохраняются в `SETTINGS.CUSTOM_FIELDS` |

Структура элемента `sheets[]`:

```js
{
  NAME: 'Имя листа в файле',      // обязательно, пустые листы пропускаются
  ACTIVE: 'Y'|'N',                 // по умолчанию Y
  HEADER_ROW: 1,                   // номер строки заголовков (>=1)
  SAMPLE_COLS: 1..10,              // число сэмплов в UI
  SAMPLE_HIDDEN: [1..9],           // скрытые сэмпл-строки
  COLUMNS: {
    col_1: {                       // ключ колонки: col_N (N = номер колонки)
      INCLUDE: 'Y'|'N',            // включена в импорт
      ALIAS: '',                   // алиас
      LETTER: 'A',                 // буква колонки
      HEADER: 'Заголовок',         // текст заголовка из файла
      MAPS: ['NAME', 'PROPERTY_CODE'],  // поля назначения (см. fields)
      MAP_SETTINGS: [              // настройки сопоставления, индексы соответствуют MAPS
        {
          TRIM: 'Y'|'N',
          CASE: ''|'lower'|'upper'|'firstupper',
          SEARCH_USE: 'Y'|'N',     // использовать для поиска элемента
          SEARCH_MODE: 'eq'|'begin'|'end'|'contains',
          IS_NEW: ''|'Y'|'U',      // применение: новые/обновляемые ('' = оба)
          DELIMETER: ',',          // разделитель множественных значений / разделов
          BIND: ''|'id'|'xml_id'|'name'|'code',  // тип привязки значения (свойства S/N/L/E/G)
          CREATE_ENUM: 'Y'|'N',    // автосоздание значений списка (тип L)
          MULTI: ''|'append'|'delete', // режим множественного свойства (MULTIPLE=Y): '' — перезаписать все значения, 'append' — дополнить новыми, 'delete' — удалить совпавшие значения
          SECTION_CREATE: 'Y'|'N', // создание отсутствующих разделов (IBLOCK_SECTION)
          SECTION_LEVEL_DELIM: '/',// разделитель уровней пути разделов
          RULES: [                 // правила обработки (движок MapRules)
            {
              TYPE: 'transform'|'skip'|'entity',
              AGG: 'AND'|'OR'|'AND_NOT'|'OR_NOT',
              CONDITIONS: [        // дерево условий, вложенность без ограничений
                {SOURCE:'col_1', OP:'eq', VALUE:'x', VALUE2:''},   // лист-условие
                {AGG:'OR', CHILDREN:[ /* вложенная группа */ ]},
              ],
              ACTION: 'replace',        // для transform/entity
              ACTION_VALUE: '...',      // aval
              ACTION_VALUE2: '...',     // aval2
            }
          ]
        }
      ]
    }
  }
}
```

Ключ листа нормализуется сервером в `SHEET1/SHEET2/...` (имя листа НЕ стабильный ключ, хранится в `NAME`).

Ответ: `{id, sheets (нормализованные), nextStepUrl (step=4)}`.

Коды ошибок: `NOT_FOUND`, `CRON_RUNNING`, `PROCESS_NOT_DONE`, `EXCEPTION`.

## 5. `fields` — список полей назначения

**Экшен:** `awz:allxls.api.profiles.fields`

| Параметр | Тип | Описание |
|----------|-----|----------|
| `id` | int | ID профиля |

Ответ: `{id, iblock_id, groups}`. Список постоянен для профиля, грузится один раз. Группы (`ProfilesHelper::getFieldGroups`):

- **Поля элемента**: `NAME`, `ACTIVE`, `CODE`, `SORT`, `PREVIEW_TEXT`, `PREVIEW_TEXT_TYPE`, `DETAIL_TEXT`, `DETAIL_TEXT_TYPE`, `PREVIEW_PICTURE`, `DETAIL_PICTURE`, `IBLOCK_SECTION` (разделы), `IBLOCK_SECTION_PARENT` (родительский раздел), `CATEGORY_PATH` (путь разделов из categoryId XML; резолвится по названиям, `|` — вложенность, `;` — несколько путей)
- **Свойства**: `PROPERTY_<CODE>` — типы S/N/L/E/G/F (+ checkbox/listbox user-типы); имя = `NAME [CODE]`
- **Цены** (модуль catalog): `CATALOG_PRICE_<ID>` и `CATALOG_PRICE_<ID>_CURRENCY`
- **Каталог**: `CATALOG_*` поля товара

Формат группы: `{NAME: 'Свойства', ITEMS: [{ID: 'PROPERTY_COLOR', NAME: 'Цвет [COLOR]', PROPERTY_TYPE: 'S', MULTIPLE: 'N', ...}]}`. Значение `ITEMS[].ID` кладётся в `MAPS[]` колонки на шаге 3.

Расширение: событие `onAwzAllxlsGetProfileFields` (модуль `awz.allxls`).

## 6. `createProperty` — создание свойства инфоблока

**Экшен:** `awz:allxls.api.profiles.createproperty`

| Параметр | Тип | По умолч. | Описание |
|----------|-----|-----------|----------|
| `iblockId` | int | 0 | ID инфоблока (обязателен) |
| `name` | string | — | Название свойства (обязательно) |
| `code` | string | `''` | Символьный код; пустой — генерируется транслитерацией названия |
| `type` | `S\|N\|L\|F\|E\|G\|HTML` | — | Тип (HTML => S + USER_TYPE=HTML) |
| `multiple` | `Y\|N` | `N` | Множественное |

Поведение (idempotent):
- Код нормализуется: транслит, все буквы заглавные, не начинается с цифры (префикс `P`), прочерки/пробелы → `_`, допустимы `[A-Z0-9_]`.
- Совпадение кода+названия (регистронезависимо) → возвращается существующее свойство (`EXISTS: true`), дубликат не создаётся; код существующего приводится к единому регистру.
- Код занят другим свойством → суффикс `_2`, `_3`...
- Создание: `CIBlockProperty::Add`, `ACTIVE=Y`, `SORT=500`, `IS_REQUIRED=N`.

Ответ: `{ID, CODE, NAME, PROPERTY_TYPE, EXISTS: bool}`.

Коды ошибок: `BAD_PARAMS`, `NO_MODULE`, `BAD_CODE`, `CREATE_FAIL`, `EXCEPTION`.

## 7. `propertycheck` — проверка существования свойства

**Экшен:** `awz:allxls.api.profiles.propertycheck`

| Параметр | Тип | Описание |
|----------|-----|----------|
| `iblockId` | int | ID инфоблока |
| `code` | string | Символьный код (сравнение регистронезависимое) |

Ответ: `{property: {ID, CODE, NAME, PROPERTY_TYPE} | null}`. Ошибок не выбрасывает (при некорректных параметрах/исключении — `property: null`). Используется как fallback после закрытия стандартного диалога создания свойства.

## 8. MAP_SETTINGS — детальное описание параметров сопоставления

Каждой паре «колонка → поле назначения» (`MAPS[i]`) соответствует элемент `MAP_SETTINGS[i]`.

### Поиск существующего элемента

| Поле | Значения | Описание |
|------|----------|----------|
| `SEARCH_USE` | `Y\|N` (умолч. `N`) | Использовать колонку для поиска существующего элемента перед созданием нового. При `Y` значение попадает в фильтр `buildFilter` |
| `SEARCH_MODE` | `eq\|begin\|end\|contains` (умолч. `eq`) | Режим сравнения: `eq` — точное совпадение (фильтр `=`), `begin` — начало строки, `end` — конец строки, `contains` — подстрока (фильтр `%` + маска `%value%`) |

Важные детали:
- Если ни одна колонка не помечена `SEARCH_USE` — элемент **гарантированно добавляется как новый** (фильтр пустой).
- Поиск выполняется по собранным поисковым полям на этапе 1 (`buildItem` mode `search`), затем по результату выбирается режим сборки: `update` (элемент найден) или `new` (не найден).

### Применение поля

| Поле | Значения | Описание |
|------|----------|----------|
| `IS_NEW` | `''\|Y\|U` (умолч. `''`) | Куда применяется поле: `''` — всегда (новые и обновляемые), `Y` — только для новых элементов (пропускается при обновлении), `U` — только для обновляемых (пропускается при создании) |

### Базовая обработка значения

| Поле | Значения | Описание |
|------|----------|----------|
| `TRIM` | `Y\|N` (умолч. `Y`) | Обрезать пробелы по краям значения |
| `CASE` | `''\|lower\|upper\|firstupper` (умолч. `''`) | Регистр: `''` — как есть, `lower` — нижний, `upper` — ВЕРХНИЙ, `firstupper` — первая заглавная |
| `DELIMETER` | строка (умолч. `,` для множественных/разделов, иначе пусто) | Разделитель нескольких значений в одной ячейке: множественные свойства, несколько разделов. Значение режется на массив; одиночное свойство берёт первое значение |

### Тип привязки значения (`BIND`)

Показывается для свойств типов `L`, `E`, `S:directory`, `S:ElementXmlID` и для полей разделов `IBLOCK_SECTION`/`IBLOCK_SECTION_PARENT`. Как интерпретируется значение из файла при резолве:

| Значение | Описание |
|----------|----------|
| `''` | Авто: резолвер сам пробует ID / XML_ID / название / код |
| `id` | Только ID |
| `xml_id` | Только XML_ID |
| `name` | Только название |
| `code` | Только символьный код (только для `E`/`G`) |

Для `S:ElementXmlID` значение само является XML_ID элемента (резолв не требуется), для `S:directory` — резолв в XML_ID записи HL-справочника (варианты привязки — по колонкам справочника). Собирается в `PROPERTY_XXX_BIND` через `Pimport::propertyBindFields`; для полей разделов — `IBLOCK_SECTION_BIND` / `IBLOCK_SECTION_PARENT_BIND`.

Кеши enum/связей раздельные для авто-режима и строгих привязок.

### Специальные опции

| Поле | Условие показа | Значения | Описание |
|------|----------------|----------|----------|
| `CREATE_ENUM` | свойство типа `L` | `Y\|N` (умолч. `Y`) | Автосоздание отсутствующих значений списка. `N` — отсутствующее значение игнорируется |
| `MULTI` | множественное свойство (`MULTIPLE=Y`) | `''` \| `append` \| `delete` (умолч. `''`) | Режим сохранения множественного значения при обновлении: `''` — перезаписать все значения, `append` — дополнить текущие значения новыми (без дублей), `delete` — удалить из текущих значений совпавшие. Собирается в `PROPERTY_XXX_MULTI` через `Pimport::propertyBindFields`, merge выполняется сервисом `Services\iblock::mergeMultiProperties` |
| `SECTION_CREATE` | поле `IBLOCK_SECTION` | `Y\|N` (умолч. `Y`) | Создавать отсутствующие разделы из пути |
| `SECTION_LEVEL_DELIM` | поле `IBLOCK_SECTION` | строка (умолч. `/`) | Разделитель уровней пути разделов (`Категория 1/Подкатегория`) |

Собираются в ключи `PROPERTY_XXX_CREATE_ENUM`, `PROPERTY_XXX_BIND`, `IBLOCK_SECTION_*` через `Pimport::propertyBindFields`.

## 9. Типы полей назначения и формат значений из файла

Значение из ячейки форматируется сервисом-приёмником (`Services\iblock`) по типу поля:

| Поле | Тип | Формат значения из файла |
|------|-----|--------------------------|
| `NAME`, `PREVIEW_TEXT`, `DETAIL_TEXT`, `CODE` и др. | поле элемента | Строка как есть (после правил) |
| `PREVIEW_TEXT_TYPE`, `DETAIL_TEXT_TYPE` | поле элемента | `text\|html`; при пустом значении тип определяется автоматически по содержимому описания (html-теги → `html`) |
| `ACTIVE` | поле элемента | `Y`/`N` |
| `SORT` | поле элемента | Число |
| `PREVIEW_PICTURE`, `DETAIL_PICTURE` | файловое поле элемента | Путь/URL → `CFile::MakeFileArray` + `EXTERNAL_ID = md5(путь)` (проверка изменения: при повторном импорте файла с тем же путём ядро не перезаливает файл, если EXTERNAL_ID совпадает с текущим); `'false'` → удаление (`['del'=>'Y']`); пустое — файл не трогается |
| `IBLOCK_SECTION` | разделы | Число → ID раздела; иначе путь по уровням через `SECTION_LEVEL_DELIM` (уровни ищутся по названию); несколько разделов — через `DELIMETER`; первый раздел основной, остальные в `IBLOCK_SECTION_LIST` (мультисекционность через `SetElementSection`); отсутствующие создаются при `SECTION_CREATE=Y` |
| `IBLOCK_SECTION_PARENT` | родительский раздел | Резолвится первым и задает базового родителя для раздела(ов) поля `IBLOCK_SECTION`; только родительский задан — он же раздел элемента. Тип привязки — `IBLOCK_SECTION_PARENT_BIND` (авто/id/xml_id/code/name) |
| `CATEGORY_PATH` | разделы из XML | Путь категорий из дерева (`|` — вложенность, `;` — несколько путей), резолв по названиям в ID разделов; синтетическая колонка `category_path` заполняется при импорте по `categoryId` строки (хеш строки — по сырому `categoryId`) |
| `PROPERTY_*` тип `S` (+user-типы) | строка | Как есть; `S:HTML` — JSON `{"VALUE","TYPE"}` или строка (TYPE авто по html-тегам); `S:ElementXmlID` — значение как есть (XML_ID элемента); `S:directory` — резолв в XML_ID записи HL-справочника (по `BIND` — ID/колонка справочника) |
| `PROPERTY_*` тип `N` | число | Нормализация числа |
| `PROPERTY_*` тип `L` | список | VALUE или XML_ID → ID enum; отсутствующее — автосоздание (`CREATE_ENUM`); `''` / `false`-семантика очистки |
| `PROPERTY_*` тип `E` | привязка к элементу | ID / XML_ID / CODE / NAME → ID элемента связанного инфоблока (по `BIND`) |
| `PROPERTY_*` тип `G` | привязка к разделу | ID / NAME / CODE → ID раздела (по `BIND`) |
| `PROPERTY_*` тип `F` | файл | Путь/URL → `CFile::MakeFileArray` + `EXTERNAL_ID = md5(путь)`; `'false'` → удаление |
| `CATALOG_PRICE_<ID>` | цена | Число; пустое/нечисловое — цена не трогается |
| `CATALOG_PRICE_<ID>_CURRENCY` | валюта | Код валюты (по умолчанию базовая) |

Множественные свойства: строка с разделителем (`DELIMETER`) → массив; массив → поэлементно; пустой массив → очистка (`false`). Одиночное свойство со списком значений (после `json_key`/разделителя) — берётся первое значение (кроме файловых структур `del`/`name`/`tmp_name` и формата `VALUE`/`DESCRIPTION`).

Обновление элемента: перед `Update` из массива загрузки удаляются поля, значения которых совпадают с текущими данными элемента (`stripUnchangedFields`, сравнение консервативное — `PROPERTY_XXX` сравнивается с `PROPERTY_XXX_VALUE`, числа без ведущих нулей, массивы с сортировкой); если после этого полей не осталось — обновление не выполняется (счётчик «Пропущено: без изменений»). Свойства пишутся точечно через `SetPropertyValuesEx` (непереданные не затираются); порядок обновления полей/свойств — `SYSTEM_UPDATE_ORDER` (см. шаг 4).

## 10. Правила обработки (RULES, движок `Awz\Allxls\MapRules`)

Порядок применения к значению колонки: `TRIM`/`CASE`/`DELIMETER` → правила `TYPE=transform`/`skip`/`entity` (в порядке следования) → пропуск пустых (`SKIP_EMPTY`).

### Типы правил

| TYPE | Описание |
|------|----------|
| `transform` | Преобразовать значение из файла: если условия выполнены — к значению применяется `ACTION` |
| `skip` | Пропустить обработку всей строки: если условия выполнены — строка пропускается (маркер `HASH_SKIP_MARK` в дедупе) |
| `delete` | Удалить элемент: если условия выполнены — собирается фильтр поиска (поля `SEARCH_USE`), найденный элемент удаляется (`deleteRowByRule`); оба хеша строки сохраняются с маркером `HASH_SKIP_MARK`. Статистика «Удалено по правилу» / «Ошибки удаления по правилу» |
| `unset` | Не обрабатывать значение: если условия выполнены — поле исключается из загрузки (`buildItem` не пишет его в элемент), строка обрабатывается штатно; ACTION не используется |
| `entity` | Преобразовать существующее значение элемента |

Структура правила:

```js
{
  TYPE: 'transform',
  AGG: 'AND'|'OR'|'AND_NOT'|'OR_NOT',  // логика объединения условий
  CONDITIONS: [ /* дерево условий */ ],
  ACTION: 'replace',
  ACTION_VALUE: '...',   // aval — первый параметр действия
  ACTION_VALUE2: '...'   // aval2 — второй параметр действия
}
```

`AGG`: `AND` — все условия, `OR` — любое, `AND_NOT`/`OR_NOT` — то же с отрицанием.

### Условия (CONDITIONS)

Лист-условие: `{SOURCE, OP, VALUE, VALUE2}`. `SOURCE` — ключ колонки (`col_N`), `__PROCESSED_col_N` (преобразованное значение колонки) или макрос (`#ELEMENT_FOUND#`, `#VALUE_FOUND#`). Вложенная группа: `{AGG, CHILDREN: [...]}` — вложенность без ограничений.

**Операторы (`OP`)** и их параметры:

| OP | Описание | VALUE | VALUE2 |
|----|----------|:-----:|:------:|
| `eq` | равно | + | |
| `ne` | не равно | + | |
| `gt` | больше | + | |
| `lt` | меньше | + | |
| `ge` | больше или равно | + | |
| `le` | меньше или равно | + | |
| `between` | от-до | + | + |
| `contains` | содержит | + | |
| `not_contains` | не содержит | + | |
| `begins` | начинается на | + | |
| `ends` | заканчивается на | + | |
| `empty` | пустое | | |
| `not_empty` | не пустое | | |
| `regex` | соответствует регулярке | + | |
| `not_regex` | не соответствует | + | |
| `any` | любое | | |

### Действия (`ACTION`) и параметры (`aval` = ACTION_VALUE, `aval2` = ACTION_VALUE2)

| ACTION | Описание | aval | aval2 |
|--------|----------|:----:|:-----:|
| `replace` | заменить значение целиком | + | |

| `cut_after` | обрезать ПОСЛЕ символа (оставить то, что до) | символ | `last` — по последнему вхождению, иначе по первому |
| `translit` | транслитерация | | |

### Макросы (в `ACTION_VALUE`, `ACTION_VALUE2`, условиях `VALUE`)

| Макрос | Описание |
|--------|----------|
| `#VALUE#` | Начальное значение колонки-источника (до правил) |
| `#VALUE_PROCESSED#` | Текущее обработанное значение цепочки правил |
| `#ENTITY#` | Значение элемента |
| `#ENTITY_<ПОЛЕ>#` | Значение поля найденного при поиске элемента (данные в `options.entity_data`, выставляется после поиска; свойства поддерживают и формат `PROPERTY_XXX_VALUE`; в полной сборке — пусто; служебные поля `IBLOCK_SECTION_PARENT`/`CATEGORY_PATH` в макросы не включаются) |
| `#COL_<KEY>#` | Начальное (сырое из файла) значение колонки `col_N` → `#COL_COL_1#`-стиль ключа (буквы/цифры ключа в верхнем регистре) |
| `#COL_PROCESSED_<KEY>#` | Преобразованное значение колонки (лениво, с кешем на строку) |
| `#ALIAS#` | Алиас колонки |
| `#ELEMENT_FOUND#` | Найден ли существующий элемент при поиске: `Y`/`N` (актуален в сборке этапов поиска/сохранения; в полной сборке — `N`) |
| `#VALUE_FOUND#` | Найдено ли обработанное значение в словаре поля назначения: `Y`/`N` (L — значение списка, E — элемент, G — раздел; обычные поля — `Y`) |

### Начальные и обработанные значения: как пользоваться

Для каждой колонки доступны **две пары источников значений** — «начальное» (сырое из файла) и «обработанное» (после TRIM/CASE и всех правил колонки). Колонка-источник задаётся ключом колонки `col_N`:

| Источник | Где используется | Значение |
|----------|------------------|----------|
| `col_N` (в условиях) / `#COL_<KEY>#` (в макросах) | условия и действия правил | **Начальное** значение колонки `col_N` — как в файле, до любых преобразований |
| `__PROCESSED_col_N` / `#COL_PROCESSED_<KEY>#` | условия и действия правил | **Обработанное** значение колонки `col_N` — после TRIM/CASE и цепочки правил этой колонки |
| `#VALUE#` | действия правил | Начальное значение колонки-источника (фиксируется в момент старта `processRules`) |
| `#VALUE_PROCESSED#` | действия правил | Текущее значение обрабатываемой колонки на шаге цепочки правил |

Ключ макроса — ключ колонки, из которого удалены все не-буквы/цифры, в верхнем регистре: колонка `col_1` → `#COL_COL1#` и `#COL_PROCESSED_COL1#`; колонка `col_price` → `#COL_COLPRICE#` / `#COL_PROCESSED_COLPRICE#`.

Практические примеры:

**1. Цена из колонки B + наценка из колонки C** (колонка B — цена, в неё же пишем результат):
```
ACTION = formula
ACTION_VALUE = '#VALUE# + #COL_PROCESSED_COL3#'   // начальное B + обработанное C
```
`#VALUE#` — сырое значение из файла (до TRIM/правил колонки B), `#COL_PROCESSED_COL3#` — колонка C после всех её правил (например, после `json_key` или умножения).

**2. Условие по обработанному значению другой колонки:**
```json
{
  "TYPE": "transform",
  "AGG": "AND",
  "CONDITIONS": [
    {"SOURCE": "__PROCESSED_col_2", "OP": "eq", "VALUE": "продано", "VALUE2": ""}
  ],
  "ACTION": "append",
  "ACTION_VALUE": " (нет в наличии)"
}
```
`__PROCESSED_col_2` — колонка 2 уже после преобразований (lower/replace и т.д.); `col_2` — то же значение «как в файле».

**3. Полное переопределение значения из другой колонки:**
```
ACTION = replace
ACTION_VALUE = '#COL_COL1# — #COL_COL2#'          // конкатенация двух сырых колонок
```

**4. Собственный код = обработанный артикул + сырой код из другой колонки:**
```
ACTION = unique_code
ACTION_VALUE = '#COL_PROCESSED_COL2#_#COL_COL3#'
```

Порядок/семантика:
- `#VALUE#` и `#VALUE_PROCESSED#` относятся **только к колонке, к которой применяются правила** (колонке-источнику правила).
- `#COL_*#` / `#COL_PROCESSED_*#` — любые колонки листа; обработанные значения вычисляются лениво с кешем на строку (правила колонки считаются один раз).
- В **условиях** (`SOURCE`) используйте `col_N` для «сырых» проверок и `__PROCESSED_col_N` для проверок результата преобразований — без префикса `__PROCESSED_` условие смотрит на начальное значение.
- Циклические зависимости обработанных колонок не разрешаются: обработанное значение колонки считается по цепочке её правил; если внутри правил колонки A запросить `#COL_PROCESSED_A#` — берётся обработанное значение на текущем шаге (аккуратно с самоссылками, лучше использовать `#VALUE#`/`#VALUE_PROCESSED#`).

Флаг пропуска строки: `MapRules::$lastSkip` — сбрасывается перед `buildItem`, проверяется после; при срабатывании skip-правила обработка оставшихся колонок останавливается.

**Запуск импорта** — `awz:allxls.api.pimport.import`:

| Параметр | Тип/умолч. | Описание |
|----------|-----------|----------|
| `id` | int | ID профиля |
| `hitTimeLimit` | int, 20 | Лимит времени хита, сек |
| `maxExecutionTime` | int, 0 | Лимит скрипта (0 — авто) |

| `fromCron` | `Y\|N`, `N` | `Y` — запуск из cron-процесса (маркер `SOURCE=cron` в состоянии, heartbeat, запись состояния раз в 30 сек; проходит через `CRON_RUNNING`-блокировку) |

Поведение `import`:
- `hitTimeLimit` ограничивается жёстким `max_execution_time` хостинга: если `set_time_limit` не работает, хит не превышает `max(10, iniMax - 15)` сек.
- На старте импорта файл-источник копируется в `/upload/tmp/awz.allxls/` (`PROCESS.TMP_FILE`) — читается снимок (живой файл может измениться в ходе многохитового импорта). Копия удаляется при `done`/`finish`/`reset`, пропавшая пересоздаётся; при `reset` очистка каталога: для каждого профиля остаются только 3 последних файла (активные копии из `PROCESS.TMP_FILE` не удаляются), прочие файлы — старше суток.
- Внешний источник (ссылка): перед обработкой кеш актуализируется с учётом TTL (`FILE_CACHE_LIFETIME`); кеша нет — ошибка `FILE_NOT_EXISTS` («дождитесь cron/агента»).
- Если ни одна колонка не помечена `SEARCH_USE`, элемент добавляется как новый; найденному элементу передаются только изменившиеся поля (см. раздел 9).

Ответ: `{finished: true}`. Ошибки: `NOT_FOUND`, `CRON_ALIVE_WAIT` (импорт выполняется живым cron-процессом — «подождите 3 минуты»; при мёртвой блокировке блокировка снимается и импорт завершается).

Экспорт: аналогично `awz:allxls.api.pexport.{settings,saveSettings,colsettings,export,finish}`; колонки экспорта `{NAME, FIELD, ACTIVE, TRIM, CASE, DELIMETER, RULES}` (RULES — только transform/skip, движок импорта `MapRules`); файл результата `/upload/awz.allxls/export/profile_<id>.xlsx|.csv|.json` (JSON — потоковая дозапись, шаблон `SETTINGS.EXPORT_JSON_TEMPLATE`, фильтр `SETTINGS.EXPORT_FILTER`), выгрузка идет во временный файл `/upload/tmp/awz.allxls/export/` и копируется по финальному пути при `done`; `finish` возвращает `file_url`. `saveParams` сохраняет `EXPORT_HIT_TIME_LIMIT`/`EXPORT_MAX_EXECUTION_TIME`/`EXPORT_LOG_ERRORS` + `EXPORT_REQUEST_DELAY` (пауза между запросами, сек, применяется JS-ом) + `EXPORT_STEP_BY_STEP` (экспорт по одному элементу, ответ содержит `debug`); JS — `profiles_edit_step4_export.js`.

| Метод хука | Экшен Pimport | Назначение |
|------------|---------------|------------|
| `awzairun.saveparams` | `saveParams` | сохранить параметры запуска (раздел 11, таблица выше) |
| `awzairun.import` | `import` | обработать один хит импорта |
| `awzairun.finish` | `finish` | принудительно завершить импорт |

Вызов:

```
POST https://<домен>/bitrix/services/main/ajax.php?action=awz:bxorm.api.hook.call&app=<ID>&key=<KEY>&method=awzairun.import
{"id": 12, "hitTimeLimit": 20, "reset": "N", "logErrors": "N"}
```

- Параметры — те же, что у экшенов (top-level, не внутри `params`): для `awzairun.saveparams` — `id, hitTimeLimit, maxExecutionTime, logErrors, hashType, hashMemCache, hashUsedColumns, skipIfNotFound, systemReplaceDate, systemFacet, systemMeta, systemSearchNew, systemSearchUpdate, systemResizePictures, systemUpdateOrder, stepByStep`; для `awzairun.import` — `id, hitTimeLimit, maxExecutionTime, reset, logErrors, fromCron`; для `awzairun.finish` — только `id`.

- Ошибки — в `errors[]`: `NOT_FOUND` (профиль не найден), `CRON_RUNNING` (выполнение занято cron-процессом; параллельный запуск запрещен).

Типовой цикл внешнего импорта через хук:

```
1. awzairun.saveparams   {id, hitTimeLimit: 20, hashType: "item", hashMemCache: "Y"}
2. awzairun.import       {id, hitTimeLimit: 20}          → {done: false, processed: 450, ...}
3. awzairun.import       {id, hitTimeLimit: 20}          → повторять до done: true
4. (при обрыве цикла) awzairun.finish {id}               → пометить импорт завершённым
```

### 11.2. Cron-запуск: `cronsave` / `cronstatus`

**Экшены:** `awz:allxls.api.profiles.cronsave` / `.cronstatus`.

`cronsave` — настройки расписания (шаг 4, блок «Расписание запуска (cron)»):

| Параметр | Тип/умолч. | Описание |
|----------|-----------|----------|
| `id` | int | ID профиля |
| `active` | `Y\|N`, `N` | Включение запуска по расписанию |
| `schedule` | string, `''` | crontab-выражение (5 полей, алиасы `@hourly`/`@daily`/...) либо пусто — используется сохраненное; валидация на сервере (`CRON_SCHEDULE_INVALID`/`CRON_SCHEDULE_EMPTY`) |
| `stepTime` | int, 0 | Время одного шага запуска, сек (0 — обрабатывать до завершения; макс. 3600) |

| `mode` | string, `''` | Способ запуска: `cron` (общее задание `run.php all`) \| `cron_own` (отдельное `run.php <id>`) \| `agent` (агент Bitrix); хранится в `SETTINGS.CRON_MODE` |

Ответ = данные `cronstatus`. При `release!=Y` и живой cron-блокировке сохранение запрещено (`CRON_RUNNING`).

`cronstatus` (параметр `id`) — статус: `{id, active, schedule, schedule_valid, step_time, pause, mode, agent (статус агента: exists/active/duplicates/next_exec/overdue), running, start_time, next_run, last_end, last_err, stats_view («живая» статистика cron-прогона из PROCESS.STATS_VIEW), source (cron|''), done, run_started, command (рекомендуемая команда CLI)}`. JS шага 4 опрашивает его раз в 20 сек при `running` и показывает баннер «Обработка запущена на crontab» + прогресс/статистику.

## 12. Веб-хук `awz.bxorm` — внешний доступ к API

Модуль `awz.bxorm` даёт доступ к методам `awz.allxls` без авторизации в админке — через веб-хук (сервисный ключ приложения). Хук и методы создаются автоматически модулем `awz.allxls` (`GenHook::createHook`, `lib/helper/genhook.php`; экшены `awz:allxls.api.genhook.create` / `.delete`).

### Точка входа

```
POST https://<домен>/bitrix/services/main/ajax.php
    ?action=awz:bxorm.api.hook.call
    &app=<ID_ХУКА>
    &key=<СЕРВИСНЫЙ_КЛЮЧ>
    &method=<METHOD>
```

Пример действующей точки входа (app, key и домен — из настроек хука на сайте):

```
POST https://utf8.zahalski.dev/bitrix/services/main/ajax.php?action=awz:bxorm.api.hook.call&app=5&key=1|p2B2mYe4N6Sau1DJ5dVl0&method=awzaiimport.save
```

Для вызова нужны три составляющие:

- **домен сайта** — например `utf8.zahalski.dev`
- **`app`** — ID хука (запись таблицы хуков `awz.bxorm`, в примере `5`)
- **`key`** — сервисный ключ хука. Формат `<userId>|<token>`, в примере `1|p2B2mYe4N6Sau1DJ5dVl0` — вызов выполняется от имени пользователя с ID `1` (его права применяются к операциям). Альтернатива: заголовок `Authorization: Token <key>` или `Bearer <key>`

`method` — вызываемый метод (см. таблицы ниже).

Аутентификация — фильтр `AppAuth` (проверка пары app+key через `Helper::checkServiceKey`), доступность метода — `CheckMethod` (метод должен быть привязан к хуку и активен в `MethodsTable`). CORS разрешён (`NoCors`).

### Методы `awzaiimport.*` (прокси на `Awz\Allxls\Api\Profiles`)

### Методы `awzaiimport.externals` / `awzaiimport.externalinfo` — профили сторонних модулей

`awzaiimport.externals` (параметров нет) — список профилей сторонних модулей:

```json

  "items": [

Модули-провайдеры подключаются двумя путями:

- через событие D7 `onAwzAllxlsGetExternalProfiles` (модуль `awz.allxls`): обработчик добавляет `EventResult(SUCCESS, ['items' => [['MODULE'=>..., 'ID'=>..., 'NAME'=>..., 'TYPE'=>'import|export', 'DESC'=>...], ...]])`

- встроенный провайдер **`esol.importexportexcel`** (`Awz\Allxls\Helper\External\EsolImportexportexcel`, подключается автоматически при установленном модуле): профили импорта из `\Bitrix\KdaImportexcel\ProfileTable` (TYPE=`import`) и профили экспорта из `\Bitrix\KdaExportexcel\ProfileTable` (TYPE=`export`), описание из `PARAMS → SETTINGS_DEFAULT.PROFILE_DESCRIPTION`. method=awzaiimport.savefile      body: {"id": 12, "file_path": "/upload/import/price.csv", "csv_delimiter": ";", "csv_encoding": "utf8", "dest_type": "iblock", "iblock_id": 5}
                                 (внешний источник: {"id": 12, "file_path": "https://example.com/price.csv.gz", "file_cache_lifetime": 7200, ...})
method=awzaiimport.filecachestatus body: {"id": 12}                       → {external, ready, age, lifetime}
method=awzaiimport.settings      body: {"id": 12}                          → листы/колонки/сэмплы
method=awzaiimport.fields        body: {"id": 12}                          → группы полей назначения
method=awzaiimport.savesettings  body: {"id": 12, "sheets": [ ... ]}       → структура sheets — см. раздел 4
method=awzaiimport.createproperty body: {"iblockId": 5, "name": "Цвет", "type": "L"}
method=awzaiimport.propertycheck  body: {"iblockId": 5, "code": "TSVET"}

method=awzaitech.upload          multipart: file=@price.csv, folder=import  (или JSON {"url": "https://.../price.csv.gz"})
method=awzaitech.iblocks         body: {"filter": "Каталог", "activeOnly": "Y"}

method=awzairun.saveparams       body: {"id": 12, "hitTimeLimit": 20, "hashType": "item", "hashMemCache": "Y"}
method=awzairun.import           body: {"id": 12, "hitTimeLimit": 20}       → повторять до done: true
method=awzairun.finish           body: {"id": 12}
```

### Дополнительно

- **Список доступных методов хука**: `action=awz:bxorm.api.hook.methods&app=<ID>&key=<KEY>`
- **Batch**: `action=awz:bxorm.api.hook.batch&app&key` — `cmd` = `{ключ: "метод?param=1&param2=2", ...}`, `halt` — прервать при первой ошибке; ответ `{result: {ключ: ...}, result_error: {ключ: [...]}}`
- **JSON-RPC (MCP)**: `action=awz:bxorm.api.hook.callrpc` + параметр `mcprpc=<версия протокола>` — ответ в формате jsonrpc `{jsonrpc, result|error, id}`
- Расширение логики — событие `onBeforeHookCallAction` (модуль `awz.bxorm`)

## 13. Технические методы (`awz:allxls.api.tech.*`)

Контроллер `Awz\Allxls\Api\Tech` (`lib/api/tech.php`) — служебные методы без привязки к профилю. Префиксы: `Authentication` + `CloseSession`.

### 13.1. `upload` — загрузка файла в /upload/awz.allxls/import/

**Экшен:** `awz:allxls.api.tech.upload` (multipart/form-data **или** JSON с `url`)

| Параметр | Тип | По умолч. | Описание |
|----------|-----|-----------|----------|
| `file` | file | — | Загруженный файл (поле формы `file`, multipart). **Либо** `url` — тогда не нужен |
| `url` | string | `''` | Внешняя ссылка http/https — сервер сам скачивает файл. Для больших файлов (~60 МБ) предпочтительнее multipart (base64 в JSON не пролезет) или этот режим |
| `folder` | string | `import` | Подпапка внутри `/upload/awz.allxls/` (транслит, `[a-z0-9_-]`; один уровень) |
| `proxy` | string | `''` | Прокси для скачивания по `url` — `http(s)://user:pass@host:port` (тот же формат, что `PROXY` в профиле) |

Поведение:
- Допустимые расширения: `csv`, `xlsx`, `xls`, `gz` (по оригинальному имени).
- **`.gz` поддерживается**: файл распаковывается на сервере (`gzdecode`) и сохраняется с итоговым расширением из имени (`price.csv.gz` → `price.csv`; если внутреннее расширение не распознано — итог `csv`). Можно заливать gz — unzip на сервере не нужен.
- Имя файла транслитерируется и приводится к `[a-z0-9_-]`; при совпадении с существующим — суффикс `_1`, `_2`...
- Место хранения — постоянное на диске сайта (`/upload/awz.allxls/import/...`), не tmp: файл доживёт до запуска импорта и пройдёт проверки `saveFile` (без `..`, реальный файл).
- Скачивание по `url`: cURL, follow redirects (до 5), timeout 300 сек, SSL-проверка отключена, HTTP ≥ 400 / curl-ошибка → ошибка экшена.
- Возвращённый `file_path` можно напрямую передавать в `awz:allxls.api.profiles.saveFile` (этап 2).

Ответ: `{file_path: '/upload/awz.allxls/import/price.csv', name, size}`.

Коды ошибок: `FILE_EMPTY` (не передан file/url или пустой файл), `FILE_UPLOAD_ERROR` (код ошибки upload), `FILE_NOT_UPLOADED`, `URL_INVALID` (не http/https), `URL_DOWNLOAD_FAIL` (HTTP-код в сообщении), `TMP_FAIL`, `FILE_EXT_INVALID`, `GUNZIP_FAIL`, `FILE_SAVE_FAIL`.

Примеры:

```bash
# multipart (60 МБ — проверьте upload_max_filesize/post_max_size на сервере)
curl -X POST "https://<сайт>/bitrix/services/main/ajax.php?action=awz:allxls.api.tech.upload" \
  -H "Cookie: PHPSESSID=..." -F "file=@price.csv" -F "folder=import"

# .gz — распакуется на сервере
curl -X POST "..." -F "file=@price.csv.gz"

# сервер сам скачивает по ссылке (опционально через прокси)
curl -X POST "..." -d "url=https://example.com/price.csv.gz" -d "proxy=http://user:pass@host:port"
```

### 13.2. `iblocks` — список инфоблоков

**Экшен:** `awz:allxls.api.tech.iblocks`

| Параметр | Тип | По умолч. | Описание |
|----------|-----|-----------|----------|
| `filter` | string | `''` | Подстрока для поиска по названию (`?NAME`) |
| `type` | string | `''` | Фильтр по типу инфоблока (`IBLOCK_TYPE_ID`) |
| `activeOnly` | `Y\|N` | `Y` | Только активные инфоблоки |

Выборка `CIBlock::GetList` (`CHECK_PERMISSIONS='N'`, с подсчётом элементов), сортировка `SORT ASC, NAME ASC`.

Ответ:

```json
{
  "items": [
    {"ID": 5, "NAME": "Каталог товаров", "CODE": "catalog", "IBLOCK_TYPE_ID": "catalog", "ACTIVE": "Y", "LID": "s1", "ELEMENTS_CNT": 1250}
  ],
  "count": 1
}
```

Коды ошибок: `NO_MODULE` (iblock не установлен). `items[].ID` передаётся в `saveFile` как `iblock_id`.

### 13.3. Доступ через веб-хук `awz.bxorm`

Методы генерируются хуком `awz.allxls` (`GenHook`) под кодом `awzaitech` (методы `upload`/`iblocks`) — см. раздел 12. Вызов: `method=awzaitech.upload` (multipart с файлом в поле `file` **или** JSON с `url`/`proxy` для скачивания на сервере; `.gz` распаковывается автоматически), `method=awzaitech.iblocks`. Пример:

```
POST https://utf8.zahalski.dev/bitrix/services/main/ajax.php?action=awz:bxorm.api.hook.call&app=5&key=1|p2B2mYe4N6Sau1DJ5dVl0&method=awzaitech.upload
```

## Типовой сценарий (для ИИ)

Через веб-хук `awz.bxorm` (раздел 12) все шаги доступны методами `awzaiimport.*`, `awzaitech.*`, `awzairun.*`:

1. (опционально) `awzaitech.upload` — загрузить файл источника в `/upload/awz.allxls/`; `awzaitech.iblocks` — выбрать `IBLOCK_ID`.
2. `awzaiimport.save` (id=0, fields) → получить `id` профиля.
3. `awzaiimport.savefile` (file_path, dest_type=iblock, iblock_id) → шаг 3.
3. `awzaiimport.settings` (id) → получить листы/колонки; при необходимости `awzaiimport.savesettings` с `COLUMNS[].MAPS` (значения из `fields`) и `MAP_SETTINGS`.
4. Если нужного свойства нет: `awzaiimport.createproperty` (или стандартный диалог + `awzaiimport.propertycheck`), затем `awzaiimport.fields` заново и подстановка `PROPERTY_<CODE>` в `MAPS`.
5. Шаг 4 — параметры запуска `awzairun.saveparams`, затем запуск импорта циклом `awzairun.import` до `done: true` (при обрыве — `awzairun.finish`). Экспорт — `awz:allxls.api.pexport.*` (через админку).
