# AWZ.AllXLS — пошаговый импорт/экспорт XLSX/CSV для Bitrix

Импорт данных из XLSX/CSV в инфоблоки Bitrix через пошаговый мастер (`/bitrix/admin/awz_allxls_profiles_edit.php`): профиль → файл → сопоставление колонок и правил → запуск.

---

## Шаг 4 — параметры запуска (кратко)

| Параметр | Назначение |
|---|---|
| Время выполнения хита | Секунд на один запрос к серверу (10–30 оптимально; импорт продолжается с места обрыва) |
| Пауза между запросами | Задержка между запросами (сек), снижает нагрузку |
| Импорт по одному элементу | Каждый обработанный элемент останавливает импорт; продолжение — кнопкой «Следующий элемент». Показывает техинформацию: значения колонок из файла, финальные значения, сработавшие правила |
| Тип оптимизации загрузки | Хеш строки / хеш элемента / без хеша (дедуп при повторных импортах) |
| Дедуп по хешам | «Все хеши в память» (быстро) или «запросом в базу на строку» (экономно по памяти) |
| Хеш: какие колонки строки | Все / только задействованные (с сопоставлениями) — изменения неиспользуемых ячеек не вызывают повторную обработку |
| Пропускать строку, если элемент не найден | Новые элементы не добавляются: строка пропускается («Пропущено: элемент не найден») |
| Обновлять дату у неизмененных | TIMESTAMP_X актуализируется у пропущенных по хешу элементов |
| Фасетный индекс / мета-теги / индексация поиска | Пересчет после изменения элементов (отключите для ускорения) |
| Тип обновления | Сначала поля, затем свойства — или наоборот |
| Писать ошибки | Ошибки строк в журнал событий Битрикса |

Статистика показывает итоговые счетчики (обработано/добавлено/обновлено/удалено/пропущено), время методов поиска/добавления/обновления (сек, вызовы, % от общего времени) и топ-10 нагруженных колонок.

## Правила обработки колонок

На шаге 3 для каждой колонки («Настройки поля» → «Правила обработки»):

- **Типы правил**: «Преобразовать значение» (transform), «Пропустить обработку строки» (skip), **«Удалить элемент»** (delete — найденный по фильтру поиска элемент удаляется, строка больше не обрабатывается), «Преобразовать существующее значение» (entity)
- **Условия** (`Если`): источник — любая колонка («начальное»/«преобразованное»), а также служебные признаки **«Элемент найден при поиске (Y/N)»** и **«Значение найдено в словаре (Y/N)»**; операторы: равно, содержит, regex, между, пустое и т.д.; группы AND/OR с отрицаниями
- **Действия**: заменить, добавить до/после, транслит, unique_code, round, арифметика, formula, `json_key`, `build_json` (шаблон финального JSON) и др.
- Действие без условий выполняется всегда.

### Примеры правил

```text
Правило 1 (skip):          Удалить старые позиции из прайса
  Тип:   Пропустить обработку строки
  Если:  [Колонка J: availability — начальное] равно "out_of_stock"

Правило 2 (delete):        Удалить элементы, которых нет в файле
  Тип:   Удалить элемент
  Если:  [Элемент найден при поиске (Y/N)] равно "N"

Правило 3 (skip):          Обновлять только существующие (без добавления новых)
  Тип:   Пропустить обработку строки
  Если:  [Элемент найден при поиске (Y/N)] равно "N"

Правило 4 (transform):     Цена со скидкой, если товар по скидке
  Тип:   Преобразовать значение; действие: formula
  Если:  [Колонка F: discount — начальное] больше "0"
  ACTION_VALUE: #VALUE# * (1 - #COL_PROCESSED_COLF# / 100)
```

### Макросы

| Макрос | Значение |
|---|---|
| `#VALUE#` | Начальное значение колонки-источника (до правил) |
| `#VALUE_PROCESSED#` | Текущее обработанное значение цепочки правил |
| `#ENTITY#` | Существующее значение элемента |
| `#COL_<KEY>#` | Начальное значение колонки KEY |
| `#COL_PROCESSED_<KEY>#` | Преобразованное значение колонки KEY |
| `#ELEMENT_FOUND#` | Найден ли существующий элемент при поиске: **Y/N** (в полной сборке до поиска — N) |
| `#VALUE_FOUND#` | Найдено ли значение в словаре поля назначения: **Y/N** |

`#VALUE_FOUND#` проверяет обработанное значение колонки в словаре поля назначения:
- свойство типа **L** (список) — по VALUE или XML_ID значения списка;
- **E** (привязка к элементам) — по ID, XML_ID, CODE или NAME элемента;
- **G** (привязка к разделам) — по ID, NAME или CODE;
- обычные поля — всегда Y.

Макросы работают в значениях действий (`ACTION_VALUE`, в т.ч. в шаблоне `build_json`) и в значениях/источниках условий.

## Примеры сценариев

### 1. Только обновление существующих товаров

Вариант А — опцией на шаге 4: включите «Пропускать строку, если элемент не найден».

Вариант Б — правилом (гибче, можно логировать):

```text
Тип: Пропустить обработку строки
Если: [Элемент найден при поиске (Y/N)] равно "N"
```
Колонка, участвующая в поиске элемента, должна иметь флаг «Использовать для поиска элемента» (например, по `sku`).

### 2. Не добавлять элементы, для которых не хватает значений списков

```text
Тип: Пропустить обработку строки
Если: ИЛИ
  - [Значение найдено в словаре (Y/N)] равно "N"
```
Например, колонка с материалом (`L. Материал [MATERIAL]`) не найдена в справочнике списков — строка пропускается.

### 3. Пометить «не найдено в словаре» и продолжить

```text
Тип: Преобразовать значение; действие: заменить на
ACTION_VALUE: {"VALUE": "#VALUE_PROCESSED#", "DESCRIPTION": "value_found=#VALUE_FOUND#"}
```
(через `build_json` для HTML-свойства — в описание попадает признак наличия значения в словаре)

### 4. Удаление элементов, отсутствующих в файле

См. правило 2 выше. Элемент, найденный по фильтру поиска, удаляется; строка помечается и не обрабатывается повторно. Счетчик «Удалено по правилу» в статистике. Удаление выполняет сам импорт — обработчики событий не сбрасывают хеши.

### 5. Техинформация в режиме «по одному элементу»

Включите «Импорт по одному элементу»: после каждого элемента импорт останавливается, и ниже показываются: значения колонок из файла, финальные значения каждой колонки (`поле = результат`), сработавшие правила с описанием условий (`условия → действие`), причина пропуска, фильтр поиска и время методов (поиск/сохранение). Кнопка «Следующий элемент» — обработать следующую строку.

## Расширение макросов из своих модулей (события D7)

Список макросов формируется в `Map::getMacros` — сторонние модули добавляют свои:

```php
use Bitrix\Main\EventManager;
use Bitrix\Main\Event;
use Bitrix\Main\EventResult;

EventManager::getInstance()->addEventHandler(
    'awz.allxls', 'onAwzAllxlsGetMacros',
    function (Event $event) {
        $event->addResult(new EventResult(EventResult::SUCCESS, [
            'macros' => [
                '#SITE_URL#' => 'URL текущего сайта',
            ],
        ]));
    }
);
```

Раскрытие — в `MapRules::expandMacros` (срабатывает при обработке значений действий и условий):

```php
EventManager::getInstance()->addEventHandler(
    'awz.allxls', 'onAwzAllxlsExpandMacros',
    function (Event $event) {
        $str = $event->getParameter('str');       // строка с макросами
        $value = $event->getParameter('value');   // текущее значение колонки
        $rowValues = $event->getParameter('row_values'); // строка файла
        $options = $event->getParameter('options');      // контекст (columns, iblock_id, element_found, ...)
        $event->setParameter('str', str_replace('#SITE_URL#', 'https://example.com', $str));
        $event->addResult(new EventResult(EventResult::SUCCESS, []));
    }
);
```

Встроенные служебные макросы: `#ELEMENT_FOUND#` (Y/N — найден ли элемент при поиске), `#VALUE_FOUND#` (Y/N — есть ли значение в словаре поля назначения: списки/привязки E/G).

## Дедупликация (хеши)

- Хеши сохраняются только после успешной обработки строки; повторный импорт пропускает неизмененные строки
- Типы: `row` — хеш сырой строки; `item` — хеш собранных значений (проверяется и строковый хеш тоже); `no` — без дедупа
- Пропущенные по правилам/удаленные строки помечаются маркером и не обрабатываются повторно
- Изменение элемента извне (обновление/удаление не импортом) сбрасывает хеши элемента — строка обработается заново

## Крон

Профили можно запускать по расписанию: агент Bitrix (`Awz\Allxls\Cron\Agents::runAll`) или CLI `php bitrix/modules/awz.allxls/cron/run.php all`. Пошаговый режим по времени (`CRON_HIT_TIME`) — за один вызов не более N секунд.
