## Module Title

# Импорт и экспорт данных на 1С-Битрикс — без ручной работы

[CENTER]**AWZ: Импорт/Экспорт XLS, CSV, XML, JSON** — один раз собранный профиль обновляет каталог, цены и фиды сам, по расписанию, а собрать его можно силами вашего ИИ-агента.[/CENTER]

## Module Code

[CENTER]Код модуля: `awz.allxls`[/CENTER]

## Short Description

[CENTER]Модуль закрывает регулярный обмен данными между сайтом на 1С-Битрикс и внешними источниками: прайс-листами, товарными выгрузками поставщиков, фидами и табличными отчётами. Вместо ручного копирования строк вы один раз описываете источник, сопоставление колонок и правила обработки — дальше импорт и выгрузка идут по расписанию, с прогрессом, статистикой и блокировками от параллельных запусков. Весь этот профиль доступен и по API, поэтому его сборку можно полностью передать ИИ-агенту.[/CENTER]

## Detailed Description

### Ключевые возможности

[CENTER]
💼 **Данные на сайте всегда актуальны.** Профиль привязан к файлу-источнику или к внешней ссылке: выгрузка поставщика обновляется сама, и каталог с ценами не отстаёт от реальности.
🔄 **Импорт и экспорт в обоих направлениях.** Загрузка выгрузки в инфоблок — и отдача своих товаров, разделов и свойств в файл для внешних систем и маркетплейсов.
⚡ **Мастер вместо правки конфигов.** Четыре шага: профиль → файл → листы → обработка. На шаге «Листы» колонки сопоставляются с полями и свойствами инфоблока, там же создаются недостающие свойства.
📈 **Прозрачный прогон.** Гаджет на рабочем столе админки показывает активные профили: статус, время работы, сколько записей обработано, примерный остаток до конца, следующий запуск и число подряд идущих падений cron-процесса.
🤖 **Сборка профиля ИИ-агентом.** В настройках модуля одна кнопка создаёт хук и методы в `awz.bxorm` и выдаёт ключ доступа — после этого агент собирает профиль импорта или экспорта по вашему текстовому описанию, без кликов в интерфейсе.
[/CENTER]

### Источник данных

[CENTER]Файл задаётся путём относительно корня сайта (например, `/upload/import/file.csv`) или внешней ссылкой `http(s)` — такую ссылку модуль скачивает в кеш на cron/агенте перед прогонами, обновляя не чаще указанного времени жизни кеша (по умолчанию — раз в 2 часа). Для загрузки по внешней ссылке можно указать прокси. Для табличных файлов задаются разделитель (запятая, точка с запятой, табуляция или свой символ) и кодировка (UTF-8, Windows-1251 или своя). Для структурированных выгрузок указываются пути до повторяющихся элементов через `->` или `/` (`items->item`, `offers->offer`), и каждый такой путь становится отдельным листом профиля — то есть из одного прайса можно одновременно загружать и разделы, и товары, и предложения.[/CENTER]

### Правила обработки

[CENTER]Для каждой колонки профиля задаются активность, обрезка пробелов, приведение регистра (нижний, верхний, первая буква заглавная), разделитель множественного значения и правила уровня строки — например, пропуск строки при пустом значении. В правилах доступны макросы вида `#ENTITY_<КОД>#`, которые рассчитываются по полям сущности: список макросов и их значение расширяются через события `onAwzAllxlsGetMacros` и `onAwzAllxlsExpandMacros`, так что собственные макросы может добавить другой модуль проекта.[/CENTER]

### Запуск и расписание

[CENTER]Профиль работает по crontab-расписанию из пяти полей или через агенты «из коробки». Модуль держит блокировку профиля на время прогона, поэтому два процесса не пишут в инфоблок одновременно; ручной запуск и редактирование настроех корректно отклоняются, пока идёт обработка, а прерванный прогон можно продолжить или завершить кнопкой «Завершить обработку» на шаге 4. Предусмотрены пошаговый режим (обработка продолжается на следующем вызове), лимиты времени работы профиля и числа итераций, ограничение времени скрипта и автоматическая остановка автопродолжения после 10 подряд идущих падений cron-процесса.[/CENTER]

### Интеграция с 1С-Битрикс

[CENTER]Модуль живёт внутри ядра D7: собственный пункт в админском меню, страницы списка и редактирования профилей и разделов (`awz_allxls_profiles_list.php`, `awz_allxls_sections_list.php` и соответствующие формы редактирования), рабочий стол с гаджетом активных прогонов, ORM-таблицы профилей и хешей, файлы языка `lang/ru`, JS-расширение, регистрируемое через `CJSCore::RegisterExt`, и AJAX-экшены вида `awz:allxls.api.genhook.create`. Профили группируются по разделам, неактивный профиль по расписанию не запускается. Приёмником и источником могут выступать инфоблоки, а также PHP-файлы ORM-сущностей проекта; часть профилей может отдавать сторонний модуль-провайдер. Экспортируемый файл размещается в `/upload/awz.allxls/`. Программное управление профилями, прогонами и сопоставлением колонок закрыто слоем API (`lib/api/profiles.php`, `pimport.php`, `pexport.php`, `map.php`, `tech.php`) и описано в `README_API_PROFILES.md`.[/CENTER]

## Options and Configuration

[CENTER]**Настройки модуля в админке** — раздел «AWZ: Импорт/Экспорт XLS, CSV, XML, JSON» → «Настройки модуля» → вкладка «Общие настройки» (файл `options.php`). Здесь находятся справочный блок со ссылкой на документацию (`https://zahalski.dev/modules/awz.allxls/`) и секция «Хук для ИИ агентов»: кнопки «Создать хук для ИИ агентов» и «Удалить хук и методы», состояние хука, выдача ключа доступа при создании, ссылки на список методов `awz.bxorm` и на `README_API_PROFILES.md`. Секция появляется, когда в проекте установлен модуль `awz.bxorm`.[/CENTER]

[CENTER]**Параметры профиля** задаются не глобальными опциями, а в мастере редактирования: название, активность, раздел для группировки, произвольное описание (видно только в админке); путь к файлу или внешняя ссылка, время жизни кеша файла, прокси, разделитель и кодировка CSV, пути до элементов; листы с настройками колонок и правилами обработки; инфоблок-приёмник или путь к PHP-файлу ORM-сущности; режим запуска и crontab-расписание; для экспорта — файл в `/upload/awz.allxls/` с расширением csv или xls.[/CENTER]

[CENTER]**Параметры гаджета** на рабочем столе: количество отображаемых профилей и показ также профилей экспорта; карточки завершённых прогонов скрываются одной кнопкой.[/CENTER]

[CENTER]**Константы и опции `install.php` / `options.php`.** Отдельных пользовательских констант вида `ADMIN_DECLINE` в модуле нет; настройки хранения — опции модуля и таблицы профилей, при инсталляции создаются таблицы для MySQL и PostgreSQL. Иных фиксируемых констант исходные данные не содержат.[/CENTER]

[CENTER]**Технические требования:** 1С-Битрикс с ядром D7 (MySQL или PostgreSQL), PHP 8.2 и выше для автоматически подключаемой библиотеки чтения таблиц `PhpSpreadsheet`; для работы хука ИИ-агентов нужен модуль `awz.bxorm`.[/CENTER]
